The native API discovers `tft_test_predictions.csv` in the project root first,
then this folder. Compose mounts the existing root CSV into this folder inside
the container. The supplied export has three classes and cannot validate the
binary checkpoint; prototype inference uses the actual model, not CSV lookups.
No research sightings or reference probabilities are automatically imported
into the live PostgreSQL database.

Synthetic history can be added explicitly with:

```powershell
backend\.venv\Scripts\python.exe -m backend.seed_synthetic --per-gewog 6
```

This adds six synthetic elephant sightings per gewog (102 total), using valid
GPS points inside the original boundaries and timestamps within the past day.
Camera IDs start with `SYNTH-`; confidence, elevation and weather are generated
sample values. Images and predictions are not generated by this command. The
website labels these records as Synthetic observation. The command creates a
`synthetic-YYYYMMDD-sightings.csv` snapshot here, and repeating the same batch
skips existing records without replacing user observations.

The current `synthetic-20261029` batch was subsequently adjusted for the demo:
10 sightings are dated 29 October in Bhutan time and 92 are older than 24 hours.
Six synthetic Gelephu records now represent Wild Boar rather than elephants.
The unchanged TFT was rerun for the selected Serzhong image and produced a LOW
Gelephu forecast (about 3.8%) alongside HIGH neighbours. This is a constructed
synthetic-data demonstration, not model validation. Original records and the
prior forecast are backed up in `synthetic-risk-before-*.json`; the updated CSV
reflects the database. `backend.explore_demo_risk` rolls all trial edits back;
`backend.apply_demo_risk --apply` explicitly applies the reviewed plan.
